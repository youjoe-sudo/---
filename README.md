# نظام متابعة الغياب اليومي — مديري التربية والتعليم بالشرقية

تطبيق **محلي بالكامل** يعمل على جهازك دون إنترنت، لاستيراد كشوف قوائم الفصول بصيغة PDF،
وتحديد الغائبين بالاسم، وتوليد ملف Excel بصيغة مديرية شرقية، وأدخاله إلى موقع المديرية
عبر متصفح حقيقي.

---

## 1) ماذا يفعل

| الوظيفة | الحالة |
|---|---|
| استيراد كشف قوائم من PDF وتعرّف تلقائي على ترويسته | يعمل — تجرب على 4 كشوف حقيقية |
| استخراج أكواد الطلاب كنصوص (لا يحذف الأصفار البادئة) | يعمل |
| البحث عن طالب بالاسم (بلا تشكيل) أو بالكود | يعمل |
| تحديد الغائبين حسب اليوم مع حفظ الاختيار | يعمل |
| تصدير Excel بخمسة أعمدة بالضبط | يعمل — ويعيد الخادم قراءة الملف للتحقق |
| مراجعة السجلات الناقصة قبل التصدير (بوابة تأكيد صريح) | يعمل |
| الأتمتة (فتح الموقع → إرفاق الملف → التحقق) | يعمل — **بانتظار إدخال رابط الموقع منك** |
| بياناتك كلها على جهازك في مجلد `data/` | نعم |

> لا توجد أي بيانات وهمية أو تجريبية في الملفات النهائية أو في الشاشات.
> الاختبارات في `tests/` تستخدم بيانات **اصطناعية** فقط.

## 2) المتطلبات

- Windows 10 أو أحدث.
- Node.js إصدار 18 أو أحدث (اختُبر على v26). يُثبَّت من <https://nodejs.org>.
- متصفح **Microsoft Edge** أو **Google Chrome** مثبّت (لاستخدام الأتمتة فقط).

## 3) التشغيل

**المرة الأولى:**
```
setup.bat
```
ثم في كل مرة:
```
start.bat
```
يفتح التطبيق على <http://127.0.0.1:5199> تلقائياً.

أو من سطر الأوامر:
```
npm run build     # بناء الواجهة (مرة واحدة أو بعد أي تعديل في src/)

```

للتطوير مع إعادة التحميل التلقائي:
```

```

## 4) دورة العمل اليومية

1. **استيراد كشف القائمة** — ارفع ملف `كشف قوائم الفصول (xx).pdf`.
   سيقرأ التطبيق الترويسة (المديرية / الإدارة / المدرسة / المرحلة / الصف / الفصل / التاريخ)
   ويعرض لك صفوف الطلاب قبل التأكيد.
   عدّل أي صف يظهر عليه **علامة مراجعة** (كود ناقص أو اسم يحتوي رمزاً غير معروف) قبل التأكيد.
   إعادة استيراد نفس الملف **لا يحذف ولا يكرر** شيئاً؛ عند اختلاف الاسم لن يستبدله تلقائياً بل يسجّل التعارض للمراجعة.

2. **الطلاب** — ابحث بالاسم أو الكود، وصحّح أي كود ناقص (زر التعديل).

3. **غياب اليوم** — اختر التاريخ ثم صنف الطالب، وحدد الغائبين بالنقر على الصف.

4. **تصدير Excel** — أنشئ الملف. سيعيد الخادم قراءة الملف المنتج ويطابق صف العناوين؛
   **لن يُعلَّن «تم التحقق» إلا بعد هذه القراءة الفعلية**.
   إن وُجد بين المحدَّدين سجل غير مكتمل، **سيوقف التصدير** ويعيد لك قائمتهم — صحّحها ثم أعد المحاولة.

5. **الأتمتة** — أدخل رابط موقع المديرية في الإعدادات ثم اضغط «تشغيل».
   سيفتح المتصفح، ويلتقط لقطات شاشة لكل خطوة، ويرفق الملف، ثم **يتحقق من المؤشرات فقط**.

## 5) صيغة ملف Excel

الملف يحتوي **ورقة واحدة فقط**، والصف الأول بالضبط وبهذا الترتيب:

| أ | ب | ج | د | هـ |
|---|---|---|---|---|
| كود الطالب | الصف | اسم الطالب | الفصل | عدد أيام الغياب |

- **عدد أيام الغياب** = `1` دائماً.
- **كود الطالب** يُخزَّن **نصاً** (تنسيق Text) — يبقى حتى لو بدأ بصفر.
- عرض الورقة من اليمين إلى اليسار.
- لا توجد أعمدة ولا أوراق إضافية. اسم الورقة هو اسم الصنف (يُنظَّف من الرموز المحظورة في Excel).

**خريطة الحقول:** الترويسة في كشف المصدر تقول `الصف الأول` و`فصل : 1 / 1`، لذا:
- عمود **الصف** ← قيمة `الصف` من الترويسة (مثل `الأول`).
- عمود **الفصل** ← قيمة `فصل` من الترويسة (مثل `1 / 1`).

هذه الخريطة موثّقة هنا لأنها أول شيء يجب مراجعته مقابل نموذج المديرية الفعلي.
إن خالف النموذج، عدّل `grade`/`section` في `server/index.mjs` (دالة `/api/attendance/export`).

## 6) ملفات البيانات

كل شيء في مجلد `data/` بصيغة JSON:

| الملف | المحتوى |
|---|---|
| `students.json` | الطلاب (الأكواد نصوص) |
| `classes.json` | الأصناف |
| `schools.json` | المدارس |
| `attendance.json` | اختيار الغائبين اليومي + سجل التصدير والأتمتة |
| `import_history.json` | تاريخ الاستيراد (أُضيف/حُدّث/تعارض/يحتاج مراجعة) |
| `settings.json` | إعداداتك (منها رابط الموقع) |
| `glyph_overrides.json` | خريطة رموز الخط المضمن غير المرمّزة |
| `backups/` | نسخ احتياطية تلقائية (آخر 20 لكل ملف) |
| `evidence/` | لقطات شاشة الأدلة الخاصة بالأتمتة |
| `roster_validation.json` | تقرير جودة الاستخراج (يُنتج بأمر `validateRosters`) |

الملفات المصدَّرة في `exports/`.

**أمان الكتابة:** كل كتابة تمرّ عبر ملف مؤقت ثم استبدال ذرّي، مع نسخة احتياطية قبل الاستبدال،
وقفل لكل ملف يمنع الكتابة المتزامنة. لا شيء يُحذف تلقائياً.

## 7) كيف يقرأ التطبيق ملفات PDF؟

الكشوف تُطبع بخط **Segoe UI مُضمّن** بترميز `Identity-H` وبجدول ToUnicode فارغ،
لذا يعيد محرّك PDF **أرقام معرّف الأحرف (GID)** بدل الحروف نفسها.

يقوم التطبيق بما يلي:

1. يبني خريطة معكوسة من جدول `cmap` للخط المضّنّ داخل الملف (`GID → Unicode`).
2. يقرأ الصفوف والأعمدة من إحداثيات النص.
3. يعكس الترتيب **البصري** (الذي يُرسم من اليسار إلى اليمين) إلى **المنطقي** العربي،
   مع الحفاظ على الأرقام والمقاطع اللاتينية.
4. يوحّد الأشكال (NFKC) ويصحّح الحروف البديلة (`ی → ي`، `ک → ك`، …).
5. الرموز غير المعروفة تُطبع `\uFFFD` ويُعلَّم الصف **للمراجعة** — لا يُخمَّن أبداً.

**الرموز غير المرمّزة** في خط Segoe UI (أشكال سياقية لا تحمل ترميزاً في جدول ToUnicode)
مُخزَّنة في `data/glyph_overrides.json` — حالياً **11 رمزاً** — بطريقتين: برقم الحرف **وببصمة الشكل**
(SHA-1 لبيانات الحرف)، حتى تبقى صحيحة حتى لو تغيّر ترقيم الحروف بين ملفات PDF مختلفة.
كل رموزها الخمسة عشر (الأصلية + الإضافية) تم التحقق منها **بعرض مخطط الحرف كبيراً ثم مطابقة النتيجة
بالصف المطبوع الفعلي** — مثل «ناصر / ماضي / موسى / مرسى / بشرى».

لا حاجة لأي OCR — النص في هذه الملفات قابل للاستخراج كاملاً.

**فحص الجودة على كشوفك الحقيقية:**
```
node server/validateRosters.mjs "C:\...\كشف (85).pdf" "C:\...\كشف (86).pdf"
```
يطبع لكل ملف: عدد الصفوف، عدد من تحتاج مراجعة، الرموز غير المعروفة، وعيّنة من الصفوف،
ويكتب التقرير الكامل إلى `data/roster_validation.json`. **لا يستورد شيئاً.**

## 8) الأتمتة — وما لا تفعله

الأتمتة تستخدم `playwright-core` مع متصفح نظامك الحقيقي (Edge أو Chrome)، فلا حاجة
لتحميل متصفح إضافي.

**ما تفعله فعلاً:**
- تفتح رابط الموقع الذي **أنت** أدخلته في الإعدادات.
- تلتقط لقطة شاشة بعد كل خطوة إلى `data/evidence/`.
- تكشف اختبار الروبوت (CAPTCHA) **قبل وبعد** الإرسال.
- ترفق ملف Excel إلى حقل الرفع إن وُجد.
- تضغط زر الإرسال **فقط** إن كان هناك **زر واحد معلَّن** بكلمة مفهومة (رفع/إرسال/حفظ/…).
- تُعلن النجاح **فقط** عند مطابقة مؤشر نجاح فعلي في الصفحة.
- تسلّم المتصفح مفتوحاً لك لإكمال العملية يدوياً في أي حالة غير مؤكدة.

**ما لا تفعله أبداً:**
- لا تتجاوز اختبار الروبوت، ولا تُعيد الإرسال تلقائياً.
- لا تخمّن محددات الموقع (selectors) الخاصة به.
- لا تُخزّن أي اسم مستخدم أو كلمة مرور في ملفات JSON أو السجلات.
- لا تُعلن نجاحاً دون تحقق فعلي مطابق.

> **حالة العمل الحالية:** رابط موقع المديرية غير مضبوط بعد، لذا سترفض الأتمتة برسالة صادقة
> تطلب إدخال الرابط. هذا مقصود: لا يمكن كتابة محددات صحيحة لموقع لم يُفتح قبلك.
> بعد أن تدخل الرابط وتشغّل العملية مرة واحدة، راجع لقطات الشاشة في `data/evidence/`
> وأخبرني بما ظهر لضبط المحددات بدقة على موقعك.

يمكّن **التسليم اليدوي** من الإعدادات (افتراضياً مفعّل): يُبقي المتصفح مفتوحاً وتُنهي أنت العملية.
أنهِه من شاشة الأتمتة بزر «إغلاق المتصفح».

## 9) الخصوصية والأمان

- الخادم يستمع على `127.0.0.1` فقط — لا يمكن الوصول إليه من الشبكة.
- لا تُرسل أي بيانات إلى أي خادم خارجي. الإنترنت يُستخدم فقط لفتح موقع المديرية عند طلبك.
- لا تُخزَّن بيانات اعتماد إطلاقاً. أي حقل يحمل هذا الاسم يُحذف من الإعدادات عند الحفظ.
- لا تُحذف البيانات تلقائياً؛ الاستبدال عبر نسخ احتياطية في `data/backups/`.

## 10) الاختبارات

```
npm test
```
15 اختباراً تغطي:
- بنية ملف Excel (الأعمدة الخمسة بالضبط، ورقة واحدة، كود نصي، أيام الغياب = 1، اسم ورقة صالح).
- الاستخراج من PDF اصطناعي (متعدد الصفحات، صفوف ناقصة، ملفات تالفة).
- مسار العمل الكامل عبر الـ API (تهيئة → صنف → طلاب → بحث → غياب → تصدير → تحقق → تنزيل).
- منع التصدير مع سجلات غير مكتملة حتى التأكيد الصريح.
- عدم التكرار وعدم الحذف عند إعادة الاستيراد.
- رفض الملفات الخاطئة، ورفض تخزين بيانات الاعتماد، وتقديم الواجهة المبنية.

تُشغَّل الاختبارات على **مجلد بيانات مؤقت** ولا تلمس بياناتك الحقيقية.

## 12) ما يلزم منك أنت إنجازه

1. **إدخال رابط موقع المديرية** من شاشة «الإعدادات» — بدونه لا يمكن تجهيز الأتمتة.
2. **تشغيل الأتمتة مرة واحدة** ومراجعة لقطات `data/evidence/` لإبلاغي بمظهر الموقع
   (شاشة الدخول، حقل الرفع، زر الإرسال، مؤشرات النجاح) لضبط المحددات بدقة.
3. **التأكد من تطابق صيغة Excel** مع نموذج المديرية الفعلي:
   أنشئ ملفاً لصنف فيه غائب واحد، وافتحه، وقارن صف العناوين وعمودَي `الصف` و`الفصل`.
4. **مراجعة السجلات المعلَّمة بالمراجعة** في شاشة «الطلاب» — في الكشوف الحالية **9 سجلات**،
   منها نوعان، وكلاهما يتطلب مقارنتك بالكشف الورقي قبل التصدير:
   - **3 سجلات بلا كود أصلاً** (صفّان في كشف 85، وواحد في 86): الاسم مقروء بوضوح لكن خانة الكود
     في مصدر الـ PDF غير مقروءة أو مفقودة. أدخل الرقم من الكشف الورقي بنفسك.
   - **6 سجلات أُنتجت من صفوف فيها طالبان متجاوران** لم يُقرن الاسم بكوده بثقة: الاسم المعروض
     قد يكون مبتوراً (مثل «ثمان» أو «النجار») أو ناقصاً. قارن السطر بالكشف الورقي وصحّح الاسم أو الكود.
   البرنامج **يرفض تصدير أي سجل معلَّم بالمراجعة** ما لم تؤكده صراحة — فلا يُصدَّر اسم خاطئ بصمت.
   بعد التصحيح من الشاشة، تختفي العلامة تلقائياً.

   <details><summary>لماذا هذه السجلات بالذات؟</summary>

   كشف المديرية يطبع طالبين جنباً إلى جنب في كل سطر، ويفصل بين المجموعتين بخط رأسي. في 6 صفوف
   كانت المسافة بين رقم أحد الطلاب واسم زميله أصغر من عتبة التجميع، فأُنتج اسم مبتور إلى جوار
   كوده الصحيح. أصلحنا الاندماج الخاطئ، وبقيت هذه الصفوف معلَّمة لأن توزيع الاسم على طالبين
   متجاورين لا يمكن حسمه آلياً بثقة — فالحسم يحتاج عينك على الكشف الورقي.
   </details>
5. إن كان اسم الصنف/الترويسة في موقع المديرية يختلف عن كشف المصدر، أخبرني لأضبطه.

## 13) استكشاف الأخطاء

| العرض | السبب والحل |
|---|---|
| «لم تُبنَ واجهة المستخدم بعد» | شغّل `npm run build` ثم أعد التشغيل. |
| الأتمتة تقول «لم يتم ضبط رابط الموقع» | أدخل الرابط من الإعدادات. |
| الأتمتة تقول «لم يُعثر على حقل رفع ملفات» | غالباً الصفحة تحتاج تسجيل دخول أولاً — أكمل يدوياً، المتصفح مفتوح. |
| «يوجد سجلات غير مكتملة…» عند التصدير | صحّح الأكواد/الأسماء من شاشة «الطلاب». |
| اسم طالب يحتوي `�` | رمز غير معروف في خط الملف — صحّحه يدوياً وأخبرني بالرمز لأضيفه لخريطة الرموز. |
| ملف Excel لا يُفتح | تحقق من `exports/` ومن رسالة الخطأ في شاشة «تصدير Excel». |

بيانات التشغيل والسجلات: `data/logs.json`، أو من داخل التطبيق في شاشة «الإعدادات».
